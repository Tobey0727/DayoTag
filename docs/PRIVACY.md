# DayoTag 隐私说明

DayoTag 面向真实生活中的声音与个人记忆。隐私不是附加功能，而是产品是否成立的前提。

## 数据如何流动

```text
设备本地采集
  -> 设备本地存储
  -> BLE 直接同步到用户手机
  -> 用户选择本地 ASR 或模型服务
  -> 手机中的 Today / Memory / Skill 结果
```

项目不建设音频中转服务器，也不提供 DayoTag 云端音频存储。用户可以选择本地 ASR，让语音转写留在手机；使用云端模型时，为完成转写、理解或问答，相关数据只会发送给用户在 App 中主动选择的模型服务商。

## 用户需要知道的边界

- 安装包不内置供所有人共同使用的模型 API Key。
- 模型服务的存储、训练、日志和跨境处理规则由对应服务商决定。
- App 生成的转写、摘要、人物、待办和记忆可能不准确。
- 原始音频、完整转写、人物关系和长期记忆属于高敏感数据。
- 设备的录音能力不能绕过所在地法律和在场人员的合理知情要求。

## 权限与用途

| 权限或数据 | 主要用途 |
|---|---|
| 蓝牙 / 附近设备 | 发现、绑定、认证和同步 DayoTag |
| 通知 / 后台运行 | 显示同步状态、维持连接和恢复任务 |
| 麦克风 | App 内需要录音的语音交互 |
| 网络 | 调用用户选择的模型 API 和检查更新 |
| 设备音频 | 转写、卡片和个人记忆 |
| 卡片与记忆 | 回看、搜索、Agent 问答和 Skill |

## 安全使用建议

1. 只从本仓库的 GitHub Release 下载 APK 和固件。
2. 安装前核对 SHA-256。
3. API Key 只填写在 App 的正式设置入口，不要发到群聊、Issue 或截图中。
4. 定期备份重要内容，并删除不再需要的音频和记忆。
5. 分享卡片和日志前先检查人物、地点、时间和对话内容。
6. 不要在会议、课堂、家庭或公共场所隐蔽录制不应被记录的内容。
7. 设备遗失或手机更换时，及时检查本地数据和模型凭据。

## 公开反馈时不要提交

- API Key、访问令牌和账号信息。
- 原始录音或完整转写。
- 未经同意的他人姓名、声音和联系方式。
- 配对码、设备唯一标识和完整调试日志。
- 可以推断住址、行程或私密关系的截图。
